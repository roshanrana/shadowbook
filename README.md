# SHADOWBOOK

**A digital-twin harness for core-ledger migration.**

> Status: Finding 1 runs end to end; Finding 2's numbers need a Docker host. See `STATE.md` and `reports/FINDINGS.md`. This is portfolio work built to production constraints; it is not a production system and does not touch real money or real data.

## For a chief architect

Core migrations don't fail on the happy path. They fail in the last two percent of reconciliation breaks, which are almost always undocumented behaviour in the incumbent — a rounding rule, a cut-off time, a fee waiver nobody wrote down. SHADOWBOOK runs a new double-entry ledger as a read-only shadow of a simulated legacy core, reconciles the two continuously at three grains, and measures how long each of twelve seeded quirks takes to surface. Separately, it kills message brokers under payday load and shows, in one table, which consumer designs lose postings, which duplicate them, and what the correct design costs in latency. Both results are reproducible from a seed.

## For an engineer

- `ledger` — Go. Double-entry, append-only, derived balances with checkpoints, ledger/available/pending with expiring holds, EOD accrual, idempotency as a DB constraint, transactional outbox to a Kafka-compatible topic keyed by account, a consumer with four swappable delivery modes (at-most-once, naive at-least-once, at-least-once + inbox, transactional). Prometheus metrics including a live global-invariant check.
- `legacy-sim` — Python. Deterministic transaction stream and header/detail/trailer EOD extracts with twelve switchable quirks (`legacy-sim/quirks.yaml`).
- `reconcile` — Python. Transaction, account-day and control-total grains; timing / model-difference / defect classification; ageing; per-quirk time-to-discovery.
- `harness` — open-model load (payday, month-end, hot keys), scripted broker kills, the A–D ablation runner, and `make report`.
- One gate: `make check` (format, lint, mypy strict, go vet, unit, integration, `-race`). CI runs the same command.

## The two findings this produces

1. **Time-to-discovery per quirk** — business day and grain at which each seeded legacy behaviour first surfaced, and how many breaks it took to isolate. **All twelve are detected**; each is measured in isolation against a control run with every quirk off, which is the only way the number means what it says. A combined run with all twelve enabled at once is reported alongside, and detects fewer — quirks compound, and saying so is more useful than hiding it.
2. **Delivery-semantics ablation under broker loss** — lost, duplicated, p99, lag and invariant status for four consumer configurations under identical chaos. The *mechanism* each configuration relies on is demonstrated deterministically in the test suite without a broker (B duplicates under redelivery, C and D do not, A loses a batch outright); the *numbers* need the three-broker chaos profile.

`reports/FINDINGS.md` is generated by `make report` and never hand-edited.

### What building it actually found

Six defects that each made a quirk permanently invisible — every one found by running the thing, not by reading it. A transaction grain filtered per-day on both sides, so a posting the legacy core moved to another date could never be matched to its counterpart. A simulator that *dropped* transactions the cut-off pushed past midnight instead of carrying them forward. A reconciler that iterated the documented calendar, and so never compared the one day Q5 exists on. A hold snapshot taken at 23:59, by which time both expiry rules agree. And a single sequential RNG, so enabling the quirk that adds a business day shifted every later draw and the per-quirk runs were not controlled experiments at all.

Two calibration limits were kept as results rather than engineered away: at small balances a day-count basis difference is arithmetically indistinguishable from a rounding difference, and with all twelve quirks enabled some become unattributable.

## Named adversarial scenarios

Each maps to a test by name.

| Scenario | Test |
|---|---|
| Q1 … Q12 | `test_every_quirk_is_detected_in_at_least_one_window` (asserts all twelve, by id) |
| Q5 only in W2, Q6 only in W1 | `test_q5_is_detected_only_in_w2_and_q6_only_in_w1` |
| ablation A | `TestModeALosesRecordsOnFailureAfterCommit` |
| ablation B / C / D | `TestRedeliveryDuplicatesInBButNotInC/{B,C,D}` |
| all modes hold the invariant | `TestAllModesPreserveTheGlobalInvariant` |
| late extract | `test_a_late_extract_is_flagged_but_still_used` |
| redelivered extract | `test_a_byte_identical_redelivery_is_not_double_counted` |
| truncated extract, bad trailer | `test_a_truncated_extract_is_recorded_not_raised`, `test_a_trailer_that_lies_about_the_total_is_caught` |
| idempotency race (64 concurrent, same key → one effect) | `TestIdempotencyRace64` |
| append-only and zero-sum enforced in the database | `TestAppendOnly`, `TestZeroSumEnforcedAtCommit` |
| duplicate key / duplicate message → 23505 | `TestDuplicatesRaise23505WithNamedConstraint` |
| determinism: same seed, byte-identical extracts | `test_two_runs_of_the_same_seed_are_byte_identical` |
| Go and Python calendars agree | `test_business_days_match_go` (1096 days) |
| hot-key, broker kill during in-flight batch | not yet implemented (M5/M6) |

## Quickstart

    cp .env.example .env
    make check       # the gate: format, lint, mypy strict, go vet, unit, integration, -race
    make demo        # Finding 1, both windows, ~2 seconds, writes reports/FINDINGS.md

`make demo` needs no containers. For the ledger and the ablation:

    make up          # one broker, two Postgres, Prometheus
    go run ./cmd/ledger
    make up-chaos    # three brokers for Finding 2
    make ablate && make report
    make down

`docs/runbook.md` covers what to do when any of it misbehaves.

## Design

`docs/shadowbook-project-brief.md` → `docs/design/01-requirements.md` → `02-hld.md` → `03-lld.md` → `04-execution-plan.md`. Decisions in `docs/design/decisions.md` (D-001 … D-019, append-only). Built under a gated, document-first lifecycle; no application code before the plan was approved, and the git history shows it.

The schema in `03-lld.md` was executed against PostgreSQL 16 *before* the design was approved, which caught two defects — a mistyped `BIGSERIAL` and a balance query that returned no row at all for an account with no checkpoint yet (D-015).

## What this does not prove

The quirks are seeded and known — this calibrates a twin's reconciliation, it does not discover unknowns. A simulator is not a core. Single-box numbers are not production numbers. Configuration D's guarantee ends at the database boundary. Finding 2's numbers have not been measured, only its mechanism. Portfolio work, not a production system.
