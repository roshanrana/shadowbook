# SHADOWBOOK

**A digital-twin harness for core-ledger migration.**

> Status: design phase. Nothing runs yet. See `STATE.md`. This is portfolio work built to production constraints; it is not a production system and does not touch real money or real data.

## For a chief architect

Core migrations don't fail on the happy path. They fail in the last two percent of reconciliation breaks, which are almost always undocumented behaviour in the incumbent — a rounding rule, a cut-off time, a fee waiver nobody wrote down. SHADOWBOOK runs a new double-entry ledger as a read-only shadow of a simulated legacy core, reconciles the two continuously at three grains, and measures how long each of twelve seeded quirks takes to surface. Separately, it kills message brokers under payday load and shows, in one table, which consumer designs lose postings, which duplicate them, and what the correct design costs in latency. Both results are reproducible from a seed.

## For an engineer

- `ledger` — Go. Double-entry, append-only, derived balances with checkpoints, ledger/available/pending with expiring holds, EOD accrual, idempotency as a DB constraint, transactional outbox to a Kafka-compatible topic keyed by account, a consumer with four swappable delivery modes (at-most-once, naive at-least-once, at-least-once + inbox, transactional). Prometheus metrics including a live global-invariant check.
- `legacy-sim` — Python. Deterministic transaction stream and header/detail/trailer EOD extracts with twelve switchable quirks (`legacy-sim/quirks.yaml`).
- `reconcile` — Python. Transaction, account-day and control-total grains; timing / model-difference / defect classification; ageing; per-quirk time-to-discovery.
- `harness` — open-model load (payday, month-end, hot keys), scripted broker kills, the A–D ablation runner, and `make report`.
- One gate: `make check` (format, lint, mypy strict, go vet, unit, integration, `-race`). CI runs the same command.

## The two findings this produces

1. **Time-to-discovery per quirk** — business day and grain at which each seeded legacy behaviour first surfaced, and how many breaks it took to isolate.
2. **Delivery-semantics ablation under broker loss** — lost, duplicated, p99, lag and invariant status for four consumer configurations under identical chaos.

`reports/FINDINGS.md` is generated by `make report` and never hand-edited.

## Named adversarial scenarios

Q1–Q12 (see `legacy-sim/quirks.yaml`) · ablation A/B/C/D · hot-key (two accounts ≥ 20% of traffic) · late extract · redelivered extract · truncated extract with bad trailer · out-of-order event · idempotency race (N concurrent same-key requests → one effect) · broker kill during in-flight batch. Each maps to a test by name once implemented.

## What this does not prove

The quirks are seeded and known — this calibrates a twin's reconciliation, it does not discover unknowns. A simulator is not a core. Single-box numbers are not production numbers. Configuration D's guarantee ends at the database boundary. Portfolio work, not a production system.
